## Matched search interface
Use a verified-frontier bank, a new interface relative to CRD-02. Expand one bank entry (start initially). Verify every outgoing edge in the source order until exhaustion, budget limit, or goal. Every exact check costs one call, including invalid and duplicate edges. A verified goal terminates immediately. A node expanded previously is excluded from the bank; merge duplicate pending destinations by retaining first arrival. All valid newly found candidates compete with prior pending candidates; trim to the bank capacity and choose the highest-priority candidate to expand next. Capacity is total persistent pending destinations after each expansion, including the next candidate. Transient per-expansion batch is bounded by outdegree; report max transient and persistent counts separately. Rejected candidates may be rediscovered by a different reached parent. A terminal non-goal node consumes no calls on expansion, but cannot be re-expanded. No hidden adjacency or terminal goal identity enters the policy. All arms use the same exact verification and charge all calls.
Policies: LIFO (latest arrival), FIFO (oldest), random priority (one fixed key per insertion), depth-first (greatest depth, latest tie), linear learned, tied recurrent learned. Same cap and call ceiling. Full-information reachability is an offline label on training graphs and a sanity check, not a test-time policy.

## Split and training freeze
Development: 512 roots, seeds 410001..410512 with CRD-02 development generator. Validation: 128 roots, seeds 520001..520128 with validation generator. Held-out: 256 roots, seeds 630001..630256 with heldout generator. Use one fresh seed per root; the former CRD-02 ranges are excluded. Train on cap-4 and cap-16 LIFO/random trajectories, 64-call ceiling, with offline labels indicating whether a pending node can reach the hidden goal along valid edges (static oracle; imperfect proxy if descendants have already been expanded). Gather only observed frontier features at scheduling decisions. Policy features: normalized candidate depth, absolute remaining depth scaled by 10, age in calls/64, observed valid indegree/4, expanded fraction of candidate layer, sibling valid fraction from initial discovery, remaining budget fraction. No IDs, seed, labels, exact future adjacency, or target identity. Feature scales fixed without test fitting.

Linear logistic baseline; 8-hidden-unit tanh tied recurrent scorer (three identical residual-input transitions h <- tanh(Wx+Uh+b), h_0=0, readout sigmoid(v*h+d)). This is a small shared-weight recurrent policy, not a full TRM architecture. Deterministic initialization, full-batch or deterministic minibatch SGD, binary cross-entropy; record exact settings in code. Fixed training epochs/checkpoint schedule, choose one checkpoint per learned architecture by validation solved count at cap 4 and 64 calls, then mean calls, then earliest epoch. Seal both before test. No test tuning. Compare caps 4/16, ceilings 32/64/128; primary comparison recurrent vs LIFO, random, depth and linear at cap 4/64. Report paired wins/losses vs depth and linear, exact two-sided sign/McNemar test, and mean realized calls. Secondary results descriptive; no claim of multiple-testing-adjusted significance. Also report false accepts (must be zero), score evaluation counts, bank counts, training sample count, parameter count, and elapsed wall time if available. CPU/RSS instrumentation via Node invocation is separate if the tool only executes JS source bodies.

This protocol deliberately charges the exact pre-verification baseline in every arm. It asks whether learned prioritization helps after arithmetic validation, rather than whether a neural net approximates exact arithmetic.
