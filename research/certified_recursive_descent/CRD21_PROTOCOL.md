## Scheduler ablations and storage
Scan: same task decomposition and lower delta machinery, rebuild eligible task list each choice. Indexed: two priority heaps (F phase then H2 phase) of one task per child (F or next child action). Use summed reach over still-competitive root actions times child width, with deterministic child ID ties; within child process legal action order. Admit child action IDs only after F phase, by streaming the one legal roster for selected child; one task per child, no second-level outcome storage. Eligibility and priority can only decrease until phase change: root lower maximum nondecreasing, root uppers constant, child lower nondecreasing. Heap keys may be stale upper bounds; on pop recompute priority using cached root dependency weights; discard if dominated, reinsert if below next stored priority (ties child ID). On new phase build heap once. Scan uses identical priority, phases and legal child action order; charge scan per candidate and dependency. WholeAction: metered CRD-19 two-step objective but retain each complete root action lower immediately, use common cheap ranking and H1 memo. Visit root actions in descending cheap lower order (ID tie); no skip except root certification. No child arena for WholeAction; same bounded numeric memo.
