## 1. Incremental envelope invariant
For each expanded node v and action a, cache L_a=p_hit+sum p_j L_j and U_a=p_hit+sum p_j U_j; each child interval contains its true remaining optimum. The child-to-parent reverse index records the exact affected action indices, including transpositions. On a changed child, recompute only those action ranges and intersect parent interval with [max L_a,max U_a]. Nonchanged parent value bounds need no upstream propagation; its changed action ranges still commit. Process pending nodes by ascending remaining action budget, so every affected child precedes its ancestors in the DAG. Stage updates, new action lists and reverse-link charges atomically; if a metered operation aborts, discard the staged interval/link changes. Completely initialized but unattached nodes may remain in the temporary planner cache; the retained successor graph only contains reachable nodes. Every previously completed snapshot remains valid; later refinement can only narrow its enclosures. This is a real-arithmetic invariant, with numerical tolerance in JS. It does not require optimal action intervals to become point values before choosing an action.

Use CRD-18 persistent indexed graph, same per-decision work allocation, exact shortcuts, sparse local formula and tie rule. FullDeadline/FullLazy retain frozen full-refresh implementation. IncDeadline/IncLazy change graph update/lookup machinery, with reverse links charged via traverseEdge and cached action reads via rangeEval. Retained subgraph copies rebuild reverse links and preserve cached ranges; charge copies and new links. Incremental refresh after a completed update checks only root presence (charged traverseNode); full reachable refresh no longer required. Atomic staging and priority queue traversal are logical work operations; JS Map allocations, comparisons and scans needed to choose the next pending node are not fully charged. The implementation uses a small pending map with scan, not a measured asymptotically optimal priority queue. Both arms use the same broad proxy with operation-specific charges, not equal physical FLOPs. Eager/lazy bounds still computed under actual quota. 

## 2. Cheap safe action snapshot and two-step comparison
At successor state with b remaining actions, m_i mandatory sensors and current feasible probabilities p_i, a locally executable single-branch plan ignores all future sensor observations and chooses the top min(3,b-m_i) terminal candidates after completing sensors. It has success probability equal to their present total mass. Early abandonment on zero feasible posterior cannot remove a possible success of the chosen candidate set; capacity permits completing one chosen branch (evicting others when necessary). Therefore
    L_cheap(s,b)=max affordable_i TopSum_(min(3,b-m_i))(p_i)
is a valid achievable continuation lower bound; empty max zero. Feasibility prophet remains upper. For each root action compute hit probability plus expected cheap lower/prophet upper of all actual conditional successors. Completing the whole cheap ranking before any costly local allocation creates an admissible snapshot. If the full planner aborts, keep this or a later valid ranking with greater selected-action lower (tie descending ID). If the cheap ranking is itself interrupted, use original deterministic probe-first fallback and conservative gap one. A cheap certificate can terminate the decision early. This is a lower bound on achievable value, not a guarantee that the cheap ranking chooses the global optimum. Selection based on one action's lower bound does not require executing the witness continuation: closed-loop regret is evaluated separately. 

IncAdaptive starts with IncCheap/deadline; selected unresolved leaf gets a warm reusable upper backup only if width >=.10 and >=2 affordable branches, otherwise expand. Fixed before test. Metered2 uses same cheap snapshot then two actual Bellman backups of exact sparse static F, using local one-step memo. All action lower values must finish before adopting the new ranking; it uses the cheap prophet action upper, so even optimal actions may have loose numerical certificates. It retains the cheap snapshot if interrupted and uses no persistent DAG. On the standard 8k cohort this reproduces mean unmetered receding2 utility; not claimed identical all action paths. This comparator charges the same proxy as graph planners. No oracle value in any policy.

## CRD-20 proposal (unregistered)
Make the early-ranking mechanism a progressive branch-wise lower-envelope computation. After cheap complete action bounds, refine individual actions by evaluating one successor local static allocation at a time; maintain the lower contribution for unrefined outcomes rather than requiring every H2 action to complete. For any unrefined term keep its previous valid interval. Exact probability-weighted interval updates preserve admissibility; selecting the highest lower action and stopping on dominance retains the same regret certificate. Meter incremental state construction, local formulas, sparse convolution, one/two-step action refinement, and graph updates on a common ledger. Compare to CRD-19 metered2 and IncCheap on new roots with budgets chosen before test. Reuse one-step outcome tables rather than regenerate them; include a strictly bounded numeric arena and actual standalone Node/Rust profiling if available. This is an independent synthetic decision model; no factoring/ECDLP result inferred.
