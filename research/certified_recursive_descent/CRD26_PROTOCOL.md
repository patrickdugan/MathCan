## Allocators and exact shortcuts
Use frozen bounded scalar Factor24 with the same Float64Array 64*(B+1) scalar slots and FIFO metadata, sharing local/alloc/deadline namespaces. Direct unbounded frozen scalar is a trace control; Scalar bounded is primary baseline. Joint computes missing affordable local top1 and top2 in one sensor-word sweep when both are requested in an allocation; otherwise frozen one-value formula. Cache both exact scalar values separately under the inherited complete descriptor and cost key. Single isolated val uses ordinary lazy calculation. EagerJoint computes both missing unsaturated top1/top2 when either is requested (including an isolated val call), even if the other is unaffordable at this query but within fixed B. Do not compute saturated or unaffordable extra values; charge both local misses, shared likelihood products once and accumulation per requested output/word. Cache lookup/read/write/eviction charged as frozen scalar. Joint and EagerJoint retain frozen canonical branch order and sparse DP, including identity branches. Skip omits all dead, unaffordable and zero-success factors and uses separate single-branch formula when exactly one feasible factor. Short adds exact at-most-two-positive-branch shortcut to Skip. Both combines Joint and Short, with joint only for simultaneously requested local values. All variants use same option costs (0 or m+1..m+3) and frozen 1e-15 support tolerance except direct max formula on retained options. No dominance claim for arbitrary correlated branches.

For positive factors, let c_i be cheapest retained positive-cost option. If two smallest c_i sum exceeds b, at most one branch can receive a success-capable allocation. If three smallest c_i sum exceeds b, at most two. For the former, take maximum affordable single local value; for latter, compare all single values and all affordable pairs i<j, t_i+t_j<=b, minimizing product of failures. If fewer than three factors treat missing c_i as infinity. This strengthens the floor(b/min c_i) certificate without discarding any feasible allocation. In the at-most-two case choose pair enumeration only if its estimated upper operation count (one charge per pair of branches plus two per positive option pair, plus one per single branch) <= the exact sparse fold's candidate count computed from option costs (sum (b-t+1), including zero), otherwise use skip-DP. Charge the branch and option scans to calculate the choice, include all affordability checks, pair products, single comparisons, initialization/option/lookups in common meter. Estimates are fixed heuristics, not runtime guarantees. DP keeps same arithmetic as frozen scalar, charge candidate combinations as before. Cache complete scalar value only after charged evaluation. Every cached value deterministic, no oracle dependence. All new stores fixed same numeric bytes; JS keys, temporary DP, public setup, oracle/evaluator/graph and fallback outside payload/proxy. No actual wall time or total RAM claim.
