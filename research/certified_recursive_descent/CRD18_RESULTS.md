## Main conclusion
The registered lazy escalation policy fails to establish an advantage under the shared weighted-work allowance. Eager deadline is the strongest point estimate in standard and deeper cohorts at 8,000 units. Warm-edge reuse reduces duplicate outcome generation, but traversal/copy charges offset the saving. At 2,000 units, per-decision quotas frequently prevent a complete root ranking; the common fallback matters. The new capacity-one relaxation is mathematically admissible and passes independent checks, but improves relatively few states in this cohort. No actual hardware or wall-clock superiority established.

## 1. Work-metered planner
All five policies use independent finite branch beliefs, sparse CRD-16 static lower allocation and CRD-15 exact shortcuts, a persistent indexed DAG and a common lower-score/tie rule. Prophet initializes the original feasibility upper; eager deadline tightens each new unresolved node by CRD-17; eager backed also computes one actual Bellman upper backup from deadline values; reuse retains the warm transition lists; lazy starts at prophet and escalates the selected unresolved leaf through deadline, warm backed bound and actual expansion as necessary. A warm transition list contains public conditional outcomes, not actual hidden state. Reuse changes representation/work, not admissibility. The new common implementation uses bottom-up reachable refresh instead of CRD-17 reverse-parent incremental propagation. The repeated refresh cost is measured by the declared proxy and can disadvantage lazy refinement.

Trajectory allowance R=2,000 or 8,000 units, environment budget b=6/8/5. Each decision gets min(R,ceil(2R/b)) units, where R is current remainder. Per-operation charges are made before the modeled operation; atomic batches are charged before execution. Interrupted operations preserve only complete valid intervals and transition lists; the last complete root ranking remains an admissible snapshot even if stale. When no completed ranking exists, use deterministic probe-first fallback (descending action ID), with conservative state interval [0,1] and action gap 1. Thus the cap cannot prevent taking a legal environment action. The fallback's ranking/actual environment transition and the common setup, exact evaluation, audit, JS allocation/sorting/string overhead are outside the planning work proxy. This is not a FLOP or wall-time cap. Per-decision quota can produce fallback while trajectory units remain. Do not interpret fallback as necessarily exhausting the total allowance.

Charge categories, all weight one: local/canonical/DAG lookup, node initialization, local-value miss, individual likelihood multiplication, allocation option and combination, deadline call, screen item sorted (proxy), deadline combination, action enumeration consumed by planner, generated outcome, leaf visit, action-range evaluation and each summed outcome, backup visit, traversal node/edge, copied node/edge. Public local possible-state enumeration precedes planning for every arm, and local posterior transition lists are precomputed. Cache reset per decision except retained graph with complete intervals and warm lists. Root selection and graph refresh are charged; exact shortcut and bound formulas use double precision. Each possible observed successor copies only reachable graph and prepared edges, charges its own trajectory copy work, and discards graph if copying cannot fit. No cross-history cache warming. Copy aborts possible in implementation, none observed here. Metered work on abandoned computations is charged; graph counts are logical entries, not physical bytes.

## 4. Capacity-one information relaxation
At a cap-one state, there can be at most one active branch j. Under the relaxed screening model of CRD-17, preserve irrevocable abandonment: an unopened branch cannot be screened while retaining the active branch. For an affordable active unready j, the controller either abandons j immediately, or pays one screen. A revealed feasible state can finish with certainty because m_j+1<=b; on failure discard j and continue with unopened screens. For an active ready j, the controller can probe k of its mutually exclusive terminal candidates before opening any other branch. Once the next branch is opened, j cannot be revisited. The highest k posterior masses maximize this prefix's success; on all failures the remaining unopened beliefs are unchanged by independence. If W(C,r) is CRD-17's deadline-screen optimum over remaining unopened branches C at budget r, define
    U_cap1 = W(C,b), if no affordable active branch;
    U_cap1 = max(W(C,b), f_j+(1-f_j)W(C,b-1)), if active unready;
    U_cap1 = max_(0<=k<=min(3,b)) [TopSum_k(p_j)+(1-TopSum_k(p_j))W(C,b-k)], if active ready.
This is the exact relaxed optimum under these special assumptions: failure-only paths reduce to the active prefix then a sequence of independent one-cost screens with deadlines; skipping j implements abandonment. The original policy embeds in the richer information model, so V*<=U_cap1<=U_deadline. The second inequality follows from dropping the capacity/abandonment constraint. No general cap>1 or correlated version proved.

Independent cap-one relaxed recursion over remaining budget, live-branch bitmask, ready-probe failure mask and active branch verifies this reduction. Three hand cases (rechecked in each cohort), 192 fresh tight root/budget checks and 384 sampled labeled-oracle nonterminal states, 576 state comparisons, 1032 relaxed reference states; max discrepancy 1.11e-16. Strict improvement on 8/576 audited states. Sum tightening 1.234889 across the 576 checks (mean .002144 probability units). All comparisons to actual oracle and unrestricted deadline pass. Bound not used by main planner arms; no claim of policy gain. The ready-active hand case with three calls and two unopened two-sensor branches exhibits U_cap1=.5 vs unrestricted .6667. The helper only covers the specified cap-one model.

## CRD-19 proposal (unregistered)
Use incremental dependency-aware Bellman backups instead of the current full reachable refresh after each lazy tightening. Store cached action intervals and reverse parent links, update a parent only when a child interval changes; charge every edge update and queue visit. Start with cheap deadline initialization, then permit warm tightening only if a prospectively fixed action-overlap/estimated-cost rule warrants it. Add an inexpensive feasible root policy lower bound before costly static child allocation so tight work quotas yield a useful fallback rather than losing all partial planning. Test on fresh roots at the same declared work allowances with identical fallback and setup, separate the effects of incremental backups, cached edge reuse and adaptive spending, and compare to CRD-18 eager deadline. Also test a direct metered receding2 comparator and a measured local Node/Rust benchmark if available. Keep a physical allocator experiment and correlated inference separate. No learned or factoring result inferred.
