## Algebra and engines
Use failure vectors f_i(r)=1-V_i(r), r=0..B, interpreted as at-most-budget local success complement. Min-product convolution (f*g)(r)=min_{0<=t<=r} f(r-t)g(t) is associative and commutative on nonnegative vectors by expanding the minimum over triples. For nonincreasing at-most vectors the all-ones vector is a neutral element: min_{t<=r} f(t)=f(r). For exact-budget vectors the usual identity would instead have value 1 at zero and infinity elsewhere; do not conflate these conventions. The best independent static value is 1-(f_1*...*f_n)(b). A feasible static witness exists under CRD-14 assumptions. This remains a lower bound on adaptive value. Skip a right-factor option whose coefficient is unchanged from a cheaper option: left vector nonincreasing makes it dominated. Can swap operands to use the smaller breakpoint support. Clip floating local probability and enforce monotonicity by taking prefix minima of failures; no tolerance-based support pruning (strict decrease). Treat dead/unaffordable leaves as identity. Numerical double arithmetic, not outward-rounded certification.

Compare direct frozen sparse scalar allocator (unbounded memo) and four new allocation engines:
- Scalar: inherited exact sparse allocation, local and deadline functions with bounded scalar FIFO cache.
- Fold: exact leaf vectors shared by canonical local continuation descriptor; sequential sparse convolution, cache full root vector.
- Prefix: cache each left-deep prefix vector as well as leaves.
- Tree: cache each balanced contiguous-subset vector as well as leaves.
Tree16: same as Tree with smaller storage. Labeled segment keys include index interval and stable local posterior IDs; do not claim permutation quotient for intermediate subsets. A vector computed at horizon h may answer any r<=h by truncation, but a smaller vector cannot answer a larger query. Root order fixed by branch index. Balanced tree can reuse unchanged subtrees after one/two branch changes; prefix favors common initial segments. No generic speedup theorem at small B. Identity shortcut and operand swapping common to all vector engines; Fold isolates this from internal cache reuse.

Each new engine uses one fixed Float64Array numeric memo payload, 64*(B+1)*8 bytes for scalar and vector modes, Tree16 uses 16*(B+1)*8. Scalar entries occupy one slot per value; vector entries reserve B+1 slots per record including deadline scalar records; same total numeric payload, different metadata capacity. FIFO circular replacement; per-entry key/horizon/length JS metadata excluded. Store complete vectors only after paying writes and eviction; read into an independent temporary vector before further cache mutations, charge every copied coefficient. No partial stored vector. Vector local formula misses use inherited metered likelihood calculation with its scalar cache disabled; leaf vector cache supplies reuse, and isolated-branch values query that same leaf vector. Deadline uses same fixed store namespace. Charge lookup, option, allocation candidate, localMiss/likelihood, vector initialization/write per coefficient via nodeInit, read coefficient via copyNode, evictions via traverseEdge; charge descriptor/segment construction one lookup plus one option per inspected segment entry, support scans via rangeOutcome, identity shortcut via rangeEval. Count these categories and event counters separately. Common proxy excludes JS metadata, temporary vectors, public setup, fallback/environment execution, exact evaluator and graph allocation overhead; no physical FLOP/RSS claim. Store resets per decision in policy tests; persistent graph copied as frozen CRD-19, no cross-sibling warming. Trace cache persists over a fixed query sequence per root.
