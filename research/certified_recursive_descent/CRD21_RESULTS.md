## 1. Mathematical and algorithmic scope

Each action retains the feasible lower and admissible prophet upper from CRD-19 cheap ranking. For each first-successor child, improve the lower first with the exact static allocation F and then with a streamed whole child action's one-step backup of F. Keep the upper unchanged. Each successful completion changes a child lower by a nonnegative delta. For every dependent root action, add the sum of the affected outcome probabilities times this delta. A full completed child action yields a valid lower even if all other child actions remain unfinished. The max of previous lower and this lower is feasible. Monotone root lowers permit a running best-action comparison; the constant root upper maximum gives the current regret certificate. Update all affected numeric rows only after paying the relevant computation, dependency and ranking charges. An interrupted task leaves the prior completed ranking usable. This preserves admissibility in exact arithmetic; JS implementation uses floating tolerances and clipping, not outward rounding. Complete unlimited evaluation yields the root max(cheap,T^2F) action lower envelope. This is not generally the optimal action value.

Scan and indexed arms share the same task decomposition, static-first then second-stage phase. Each child task priority is summed reach over still-competitive root actions times child width. Root maximum lower never decreases, root uppers constant, child width never increases. Consequently a previously stored priority is an upper bound on its current priority within a phase. Lazy pop recomputes the score, discards dominated tasks or reinserts if the next stored key exceeds it. This selects the same max priority as a full scan when computation is unrestricted, including deterministic record-ID ties. Phase transition builds the heap once. Actual code keeps only one pending task per child; second-stage tasks complete one whole child action before updating its root dependency sums. Separate WholeAction control computes metered two-step action lower scores in descending cheap-lower order and commits each completed whole root action; there is no persistent graph. It reuses the first-step deterministic memo. All new methods reset their value cache at each decision, same public pre-intern setup and action fallback as CRD-19. No sibling sharing or hidden-value access.

The priority heuristic measures uncertainty weighted by reach, rather than expected improvement from computation. Queue operations and memory maintenance are explicitly charged. The extra record initialization and duplicate cheap bound extraction in the streaming planners can contribute to initial-ranking overhead; the original cheap ranking itself is preserved before arena admission. The comparison between indexed and scan isolates task selection within the same streaming machinery. Comparisons with CRD-20 weighted and CRD-19 metered2 also change decomposition and cache layout. No equal physical FLOP claim.

## 2. Numeric arena

For Scan and Indexed96: 96 x 8 float64 slots = 6144 bytes, Int32 heap capacity 96 = 384 bytes, shared 128 float64 memo slots = 1024 bytes, total fixed typed-array payload 7552 bytes. Scan allocates the same unused heap array. Indexed32: 2048 + 128 + 1024 = 3200 bytes. WholeAction allocates only the fixed 1024-byte numeric memo. Record types are root actions, root outcomes/dependencies, unique first successor records and second-level action records. Second-level outcomes streamed during one task; no admitted roster of those outcomes. Admit a complete roster of child actions only if it fits; otherwise mark blocked. Arena has no record eviction. FIFO deterministic memo with shared 128 entry capacity for local/static/H1 numeric values, namespace-prefixed string keys, charged writes and evictions. Metadata, public model, temporary root snapshot/rosters, allocation DP work arrays, JS descriptors, key map, arrays of dependency/action references and evaluator stack outside typed-byte count. These bytes describe per-planner typed payload, not total allocator use, RSS or peak of the exact evaluator (which retains recursive frames). The 128-entry memo did not bind in the frozen policy evaluations (max occupied 117, zero evictions). Separate post-campaign diagnostics exercise the limit; no policy performance under frequent memo eviction established.

## 6. CRD-22 proposal (unregistered)

The simple whole-action comparator remains the strongest practical new baseline. Test an interruptible per-root-action H2 policy with a prospectively frozen ordering based on cheap lower, certified upper gap, and estimated action computation cost. Add an equal-memory/equal-work bounded memo ablation (8/32/128 slots; FIFO vs reuse-aware eviction), with explicit persistent cache on actual observed histories only. Use cheap one-step and full metered2 references; preserve numerical interval certificates. To distinguish computation scheduling from policy quality, test on fresh roots and include larger independent branch populations where transpositions and evictions can occur, then separately profile actual Node/Rust RSS and latency. Do not infer original factorization or ECDLP results from the synthetic scheduler.
