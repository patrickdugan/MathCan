## 1. Hybrid lower-envelope mechanism
Use the CRD-19 complete cheap action ranking. A hybrid spends at most floor(one quarter of the initial per-decision quota) additional units, capped by the remaining quota, on one complete H2 action, with either cheap-lower (constant-cost) or upper-gap ordering. H2 is the two-step actual Bellman lower backup of exact sparse static allocation F. Completed H1 successor values enter the bounded deterministic memo, even when the root H2 calculation aborts. A newly initialized matching graph node may use a memoized H1 value to increase its lower, since H1 is an attainable value. If its cache entry was evicted, ordinary lower initialization applies.

Remaining work goes to incremental Bellman propagation. At a completed graph ranking, intersect each root action interval with its previously recorded cheap/H2/graph interval:
    L_a <- max(L_a, L_graph,a), U_a <- min(U_a,U_graph,a).
Both intervals enclose Q*, so their intersection is admissible in exact arithmetic. Select largest lower with the existing quantized deterministic tie rule. Do not put an externally strengthened action value in a cached edge sum: node lower and action sum have different roles. A matching completed graph ranking supplies the actual selected action and its successor graph; on interruption retain the previous numeric snapshot and only reuse a graph when the snapshot has matching attached transitions. All graph updates and snapshot merge scans charged. H2 subquota is temporarily enforced by the same meter and restored even on abort. This is an anytime admissibility result, not a guarantee that hybrid expected success dominates another policy at finite computation.

BoundedInc uses the same new cache and root-interval intersection machinery, without the H2 reservation. It isolates H2-stage addition within the new engine. It differs from the frozen IncCheap also in merged-snapshot selection and extra memo lookups, so its difference from IncCheap is not a pure causal estimate of cache size alone. Exact shortcuts, incremental propagation and graph copy otherwise reuse frozen CRD-19. Both graph and H2 policies still depend on the independent-branch finite model, not arbitrary real proof search.

## 2. Capacity-aware information upper
Let D(s,b) be the CRD-17 unrestricted deadline-screening relaxation. At a saturated capacity state with an affordable unopened branch, preserve the original first-action abandonment constraint in a relaxed screen model. For each legal first screen a on branch i, with feasible mass f_i and m_i remaining mandatory sensors, m_i+1<=b, reveal its hidden state after paying one call. Feasibility allows completion in m_i additional calls and certain success; on infeasibility remove i and any actual first-action eviction victim e(a). Use unrestricted D thereafter:
    C_screen(a) = f_i + (1-f_i) D(s minus {i,e(a)}, b-1).
For a ready terminal probe use its actual conditional outcomes:
    C_probe(a) = p_hit + sum_failure p_o D(s_o,b-1).
Then U_cap(s,b)=min(D(s,b),max_legal a C(a)). Every original policy can be bounded by one such first-action continuation. Given a feasible screen, success at most one; given an infeasible screen, extra observations on that branch have no predictive information for other branches by independence. Removing it and allowing unrestricted subsequent capacity/abandonment cannot lower the optimistic attainable success. Actual ready probe follows the original law. Thus V*(s,b)<=U_cap(s,b)<=D(s,b). This is a one-step relaxation, not the exact capacity-two relaxed optimum. The code applies it only at unresolved saturated states with an affordable unopened branch, charging actual relaxation work; numerical use is not outward-rounded.

## 3. Cache implementation and scope
Linked LRU uses fixed 32 Float64 values plus 32 Int32 previous and 32 Int32 next indices, 512 typed bytes, equal numeric payload to CRD-22's 32 float64 values/timestamps. Keys and JS Map metadata outside numeric payload. With key lookup, moving an occupied record to head or selecting tail victim uses constant link operations in slot capacity; no worst-case JS Map runtime guarantee. Charge each link write (six for detach/attach, four new insertion), one access touch, and eviction/write. Contrast linear-scan LRU which charges one timestamp touch and C comparisons on eviction. Each cache write and recency mutation pays all charges before mutation. Cache size checked. Local/static/H1/deadline namespaces share the arena. Linked32 and Carry32 use whole-root-action cheap-lower ordering. Carry32 selects only L namespace entries matching still-live affordable continuation descriptors at budgets between m+1 and current remaining calls, preserves MRU-to-LRU order, charges descriptor/option lookups, inspected cache entries and copied entries. On copy failure discard; no counterfactual sibling warming. Filter is a conservative reuse heuristic, not a complete future reachable-value set. Local values are deterministic and reused safely when keys match. Copy restoration and JS object allocations outside proxy, same caveat as CRD-22. Graph and other temporary storage not capped by 512-byte cache payload.

Independent linked cache unit diagnostic (same deterministic diagnostic repeated across cohorts): 2692 checks, 744 evictions; compares random small-cap 8/32/128 operations against an insertion-ordered reference LRU, validates linked structure, exact numeric payload and interrupted full-cache write atomicity; selective filter unit check. 189 additional path filter comparisons against independently enumerated allowed keys. No hardware memory cap.

## 7. CRD-24 proposal (unregistered)
Stop allocating a fixed H2 reservation. The primary scaling bottleneck is repeated static allocation work for nearby successor states. For independent branches define failure polynomial coefficients f_i(t)=1-V_i(t). Under min-product convolution, (f*g)(r)=min_{0<=t<=r} f(t)g(r-t), truncated to budget B, with neutral coefficient vector representing zero allocated calls and zero utility. Associativity follows by minimizing over triples of nonnegative allocations summing to r, since factors nonnegative. One branch change or eviction changes only one or two factors. Test exact shared prefix/suffix products or a persistent small convolution tree to reuse unchanged branch factors; include direct sparse convolution as strong control, since B is small and asymptotic improvement in n need not save operations. Evaluate exact F and all first/second successor values under matched work and bounded storage before any learned scheduling. Avoid eager H2 attempts that cannot complete: compare incremental-only, cheap feasible lower with selective factor reuse, and a fixed work-calibrated H2 gate on fresh roots. Register separately, include actual byte counts and controlled Node/Rust timing if possible. Original factorization and ECDLP proof audits remain separate.
