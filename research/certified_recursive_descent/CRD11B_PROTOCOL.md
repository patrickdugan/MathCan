# CRD-11B | Remove inference-time local Bellman computation
Registered after CRD-11A receipt 7f9561c7e7af42f2faf6d96029a241278090b146 and before generating new evaluation roots. Main CRD-11A implementation blob 724e924ec1403f5ce2be52e99f324ed8925c1ecb. Motivation: learned heads receive exact local DP features and do not yet establish an inexpensive amortized utility gain. This is a follow-on ablation, not an original CRD-11A endpoint.

Retrain linear/MLP/recurrent on the same deterministic CRD-11A teacher rows and same validation roots, masking four local-DP feature coordinates (zero-based 9,10,12,18) to zero. At inference compute the other sixteen features directly, bypass all local.value and local.q calls; count zero local DP states/transitions as a hard gate. Keep original feature dimensions and architecture, seeds, optimizer, training state sampling, epochs and selection rule identical. Frozen full-feature heads from CRD-11A serve as controls (do not refit). All other policy code unchanged. Sensor expected-next-max calculation and exact integer posterior updates remain allowed. Teacher generation can still use the exact Bellman DP; its cost is offline, not deployment scoring.

Fresh OOD roots 1780001..1780192, three branches, each 1–3 sensors, cap2, budgets4 and6. Primary budget6: cheap recurrent vs sensor-aware, cheap linear/MLP, full recurrent and exact local lookahead; compare full/cheap inference features and separately counted local DP/rollout states and transitions. Additional controls marginal, rollout and optimal. Report mean conditional success, regret, expected calls, probes, sensors, eviction counts, paired root bootstrap intervals (2000 resamples fixed seed), and all null/negative results. Budget4 descriptive. No test tuning. Independent forward world audit on first four fresh roots, both recurrent heads and optimal at budget6. Do not infer physical CPU/RSS speed from work counts.
