# Finite native storage bounds for certified Horn search

V16 engineering companion. For the V11 public generated graph family, n<=18 facts, initial three known facts, at most 45 rules, each with cost in 1..7 and 1..3 earlier premises. Every legal path derives a new fact once. Hence at most n-3<=15 rule applications, path cost <=105, and at most 2^(n-3)<=32768 exact reachable-state masks. A byte can encode each rule ID (0..44), path length (0..15) and a valid path cost (0..105) with 255 reserved for absence. A 32-bit state mask and 64-bit rule mask suffice. A 16-bit residual-storage index suffices if allocated at most once per known-set state. All capacities depend on the stated domain.

Residual costs are nonnegative and at most 7 under positive cut subtraction. A residual hmax distance for any derivable unknown fact is at most a topological proof cost <=105; known facts have distance zero. By the cut admissibility lemma, accumulated charges plus residual goal hmax never exceed the true remaining optimum <=105, so charge and certified bound fit in a byte. No wraparound is needed. Additive FF relaxation may count shared prerequisites repeatedly and must be computed in wider integers. This is not a proof of correctness of arbitrary native input parsing, allocator bookkeeping, or the implementation. For changed n, cost range, rule arity or scope, reestablish capacity and arithmetic bounds. Native V16 uses immutable original rule IDs and exact bitset keys; full trace matching against independently audited Python reference provides finite development evidence (108 cases, 5867 search events and 4716 charged cuts), not a kernel-checked program refinement theorem. No Lean check. See DataGoblin PR #89.
