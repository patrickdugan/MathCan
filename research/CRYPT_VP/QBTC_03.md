## Source audit

Kretschmer, Qian, Tal, arXiv:2411.02554v1, https://arxiv.org/pdf/2411.02554v1, printed pp. 2, 11-12, 16, 22 and 25: Theorem 1 references Song for signatures; Definition 11(ii) imposes pointwise quantum evaluation success >=2/3 for the entire function output; Proposition 20 uses a summable union bound and finite exceptional inputs; Proposition 28 constructs the trapdoor primitive, and Theorem 32 gives oracle-relative one-wayness. The source defines F(pk,x) with pk 3n bits, x n bits, output 6n bits. G generates the public parameter from an n-bit trapdoor, and I inverts in the image using the trapdoor. Each output bit is represented by a Forrelation block; the block length for the trapdoor construction is 2^(15n). The proof is relative to a sampled classical oracle and asymptotic; for its probability-one statement the finitely many bad inputs can be corrected in the algorithm description. That existence result supplies no finite scalable physical construction of the oracle or its exceptional-input table. This note never treats a random explicit toy function as an implementation of the oracle. 

Fang Song, arXiv:1409.2187, https://arxiv.org/abs/1409.2187, Sec. 5.1: generic one-way-function-based hash-tree signatures with post-quantum security against quantum attackers in the classical signing-query model. KQT invokes this reduction for its general signature existence claim. We isolate the elementary one-time Lamport layer, with a direct reduction in the ideal deterministic-function model; we do not implement or claim to have independently audited the entire many-time compiler.

## Conditional one-time raw-message construction

Let the KQT primitive have public parameter P produced by Gen. Fix polynomial message width L and an injective canonical encoding of all authorized spend context into L bits. For each i=0..L-1 and b in {0,1}, sample independent uniform n-bit secrets x[i,b]. Publish P and y[i,b]=F(P,x[i,b]); retain the secrets, and DO NOT retain any inversion trapdoor for P as wallet material. Sign exactly one distinct message m by revealing x[i,m[i]] for every i. The ideal verifier checks every equality F(P,s[i])=y[i,m[i]] and all lengths; the actual verifier evaluates F with fresh quantum registers. Both key and signature are classical strings. For key generation amplify to make all 2L commitments correct, union bound over calls; a rare parameter-generation error is also accounted for. The one-time construction does not use the trapdoor for signing or verification. A KQT qOWF alone would suffice. 

Ideal one-time EUF-CMA reduction sketch: given one-wayness challenge (P,Y=F(P,X)) with uniform hidden X, choose uniform hidden index (i,b) among 2L slots, fill other slots honestly, set y[i,b]=Y. Distribution of public commitments matches honest ideal keys. Answer at most one classical signing request unless it needs the hidden slot, in which case abort. If a valid fresh message m' is forged after signing m, choose a differing bit with m'[i]=b; there is at least one such slot. With no prior signing request any slot used in m' is eligible. Couple the real game with the random embedded index; on a successful forgery the probability of landing in an eligible slot is >=1/(2L). Extract s[i] to invert Y (any preimage suffices, so injectivity is unnecessary for this reduction). Thus inversion success >= forging success/(2L), up to generation/evaluation simulation errors. Amplify pseudodeterministic calls to negligible per-call error; the union bound applies to polynomially many calls, with classical adaptive signing messages and fixed-oracle pointwise error bounds. We make no claim for coherent signing queries. Maliciously generated public keys are a separate ledger policy; unforgeability concerns honestly generated keys.

One-time constraint: observing two distinct messages exposes both slot secrets at every differing bit. In the raw L-bit domain, if their Hamming distance is h, this allows 2^h messages to be signed using those revealed slots, including the two original messages. A signer must persist the first signed message before releasing a signature and never sign a different replacement using that key. Rebroadcasting the same byte-identical message is fine. Reorg, RBF and CPFP must be designed around this restriction; an unbroadcast signed spend still counts as signing. A multi-use construction or authenticated delegation tree requires its own assumptions and resource review.

## Uniform quantum verifier gap

For each well-formed P,x, Def. 11(ii) makes the correct full output a >=2/3-probability mode. Repeat t odd times and return the full string if it has a strict majority, otherwise reject/flag failure. This is not bit-wise voting and requires no assumption of independence across the bits of a single output. Assume independent fresh trials of the specified ideal evaluator. A failed decode has probability at most

q_t = 3^(-t) sum_{j=0}^{(t-1)/2} binom(t,j) 2^j.

If all L selected evaluations decode correctly, the decision agrees with the ideal deterministic relation, on valid and invalid evidence alike. Thus a per-verification error bound L q_t holds uniformly even for malformed (deterministically rejected) or adversarial well-formed inputs. A union bound N*T*L*q_t holds over N validators and T attempted verifications per validator, including adaptive attempts under the conditional fresh-run guarantee. Independence between validators is not needed for the union bound. This resolves the specific midpoint problem of QBTC-02 for the ideal interface with sufficient amplification; it does not produce deterministic consensus, global lifetime agreement, calibrated hardware error guarantees, or an efficient realizable oracle. Without a uniform guarantee for physical oracle calls the midpoint countermodel still matters.

For N=1000, T=10^6, L=256, exact binomial arithmetic gives minimal odd repetition t=1143 for total bound 2^-64, and t=1891 for 2^-128. Each verification therefore needs up to 292608 or 484096 full F-evaluator invocations respectively. These are conservative reliability-budget examples at the stipulated worst-case 2/3 success, not gate counts, timings, or concrete cryptographic security levels. The 18 registered budget cases compare exact integer tails and preceding odd t. 

## Byte costs and Bitcoin integration limits

Public key (3n+12Ln) bits, signature Ln bits, raw secret table 2Ln bits, before framing. For n=128 and L=256 these are 49,200, 4,096 and 8,192 bytes. At n=128, L=8192 they are 1,572,912, 131,072 and 262,144 bytes. The illustrative parameter n=128 has no proven 128-bit concrete security level. A digest-sized width is only a cost example; in an actual collapse world one cannot simply assume ordinary SHA256 transaction digests, address hashes, Merkle commitments, txids, or proof of work remain secure. Standard computational collision/second-preimage or preimage assumptions may fail under P=NP, asymptotically. Use raw injective bounded message encoding for this construction, or introduce and separately prove a quantum-computable collision-resistant commitment with the correct oracle-relative security notion. A fixed finite-length hash alone supplies no binding theorem. The model also needs ledger identity, uniqueness, transaction-reference and mining/consensus assumptions beyond signatures. Full public keys cannot be replaced by conventional hashes without a separate binding assumption. No existing Bitcoin script/version is proposed to accept these keys. The construction is prospective for a new ledger semantics, or a conditional experimental testnet, not a migration prescription for actual Bitcoin.

The 4-bit message / 3-bit secret fixture uses an explicit injective public arithmetic table, with fixed distinct toy secrets. It is deliberately easy to invert and has no one-wayness; it tests only data flow and equality binding.
