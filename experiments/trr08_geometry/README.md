# TRR-08 to TRR-11: exact interpolation on actual Weierstrass points

This separate Lean project connects the polynomial obstruction in the root
MathCan library to Mathlib's nonsingular affine Weierstrass points. It pins
Mathlib **v4.35.0** (commit
`56a005855ea17e0b0958f73ec801ae140b0a1679`) and uses the root MathCan package
through the path `../..`.

## Current endpoint: TRR-11

`TRR08Geometry.tame_general_polynomialDecoder_degree_iff` proves that the exact
ordinary total-degree bound in each input coordinate pair is `ceil(N/3)`.
It applies to every smooth generalized Weierstrass model with finite odd marked order
`N >= 19`, when `2`, `3`, and `N` are nonzero in the field, and to every
assigned identity value `u`. Its decoder is an actual four-variable
polynomial evaluated on the nonidentity subgroup points. Arbitrary fields,
finite extensions and odd composite orders are included.

The combined audit checks 217 principal reports. TRR-11 proves the actual
point-group equivalence with a short model and transports the polynomial
degree and assigned identity value in both directions. See the
[TRR-11 overview](../../research/translation_rank_rigidity/trr11/README.md),
[proof review](../../research/translation_rank_rigidity/trr11/proof_review.md),
and [kernel receipt](../../research/translation_rank_rigidity/trr11/formalization_receipt.json).
The [TRR-10 construction](../../research/translation_rank_rigidity/trr10/README.md)
provides polynomial residue moments and the matching point-mass decoder.
The [TRR-09 finite derivation](../../research/translation_rank_rigidity/trr09/FINITE_DERIVATION.md)
supplies the underlying residue eigenvector exclusion. The sections below
describe the original TRR-08 layer used by these theorems.

## What the declarations express

`TRR08Geometry/MarkedPoints.lean` uses the group law on
`WeierstrassCurve.Affine.Point`. For a marked point `T` with
`19 ≤ addOrderOf T`, it proves that the first nine positive multiples are
nonidentity points with distinct affine x-coordinates. A coincidence between
two coordinates would identify the points or their negatives; the resulting
multiple of `T` has index at most eighteen.

The same module derives a nonzero tangent denominator whenever a nonidentity
point has nonzero double. In short normal form, it obtains the curve equation,
the usual x-coordinate formula for doubling, and the nonzero quantity
`4 * a₄^3 + 27 * a₆^2` from Mathlib's ellipticity hypothesis.

`TRR08Geometry/Obstruction.lean` supplies those concrete facts to
`MathCan.TranslationInterpolationRootBound.doubling_data_force_singularity`.
Its theorem `tame_coefficient_exclusion` assumes two identities for a function
`a : ℕ → K`, where `n = addOrderOf T` is nonzero in `K`:

\[
a_k^2=n\bigl(x(kT)+c\bigr),\qquad
a_{2k}=2a_k+n\frac{3x(kT)^2+A}{2y(kT)}.
\]

The first identity is required when `kT ≠ O`, and the second when both `kT`
and `2kT` are nonidentity points. With `2 ≠ 0` and `3 ≠ 0` in the field,
these identities imply `False` on a smooth short Weierstrass curve of the
stated marked order. The root-count argument and the characteristic-five
branch are supplied by the imported MathCan theorem.

`TRR08Geometry/PointIdeals.lean` applies Mathlib's injection of affine points
into the ideal class group of its coordinate ring. The ideal of a finite
nonsingular point cannot be generated by a single nonzero coordinate-ring
element. This gives a concrete target for the divisor contradiction in the
matching-characteristic case.

## TRR-08 boundary and its successors

The original `tame_coefficient_exclusion` retains its two explicit coefficient
hypotheses. TRR-09 proves them for the finite coefficient constructed from
the actual residue eigenvector. TRR-10 derives that eigenvector equation
from the actual coordinate degree bound and supplies a polynomial at the
matching upper bound.

TRR-11 supplies the degree-preserving change from generalized models to
short form. In matching characteristic, the connection
from a p-th-power function and its global divisor to the concrete affine point
ideal still requires a formal proof. Small-order certificates also need their
Lean interpolation interface.

## Build

From this directory, with the pinned Lean toolchain installed:

```sh
MATHLIB_NO_CACHE_ON_UPDATE=1 lake update
lake exe cache get Mathlib.AlgebraicGeometry.EllipticCurve.Affine.Point Mathlib.AlgebraicGeometry.EllipticCurve.NormalForms Mathlib.GroupTheory.OrderOfElement Mathlib.Tactic.LinearCombination Mathlib.Tactic.Ring Mathlib.Tactic.FieldSimp Mathlib.Data.List.FinRange Mathlib.LinearAlgebra.Lagrange Mathlib.Algebra.BigOperators.Group.Finset.Defs Mathlib.Algebra.BigOperators.Ring.Finset Mathlib.Algebra.Group.Equiv.Basic Mathlib.Algebra.MvPolynomial.Degrees Mathlib.Algebra.MvPolynomial.Eval Mathlib.Algebra.MvPolynomial.CommRing Mathlib.Algebra.BigOperators.Fin Mathlib.Algebra.Polynomial.Eval.Degree
lake build
```

The project's source files print their axiom dependencies for inspection.
The target is intended to be checked with the ordinary Lean kernel; no
`native_decide`, `sorry`, or added mathematical axiom is required.
